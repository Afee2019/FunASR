# 003 - 实时语音输入集成指南

## 概述

本文档介绍如何使用 FunASR 实现类似聊天输入框旁「麦克风按钮」的实时语音转文字功能。FunASR 提供了完整的 WebSocket 流式识别方案，支持三种识别模式，并自带可直接使用的 HTML5 演示页面。

### 整体架构

```
浏览器 / 客户端                          服务端
┌──────────────────┐              ┌──────────────────────┐
│  麦克风录音       │   WebSocket   │  FunASR WSS Server   │
│  (PCM 16kHz)     │ ──────────→ │                      │
│                  │              │  VAD (语音检测)       │
│  显示识别文字     │ ←────────── │  ASR (流式/离线识别)   │
│                  │  JSON 结果   │  Punc (标点恢复)      │
└──────────────────┘              │  SV (说话人识别)      │
                                  └──────────────────────┘
```

---

## 一、三种识别模式

| 模式 | 说明 | 延迟 | 精度 | 适用场景 |
|------|------|------|------|---------|
| `online` | 纯流式，边说边出字 | 最低 (~480-600ms) | 一般 | 实时字幕、语音输入 |
| `offline` | 说完后一次性识别 | 较高 | 最高 | 文件转写、高精度需求 |
| `2pass` | 先流式出初步结果，说完后离线纠正 | 流式部分低延迟 | 高 | 兼顾体验和精度（推荐） |

**推荐使用 `2pass` 模式**：用户说话时实时显示初步结果（体验好），说完后自动用离线模型纠正（精度高）。

## 二、快速体验（5 分钟跑通）

### Step 1：安装依赖

```bash
cd ~/dev/FunASR
uv pip install -e .
uv pip install torch torchaudio websockets flask
```

### Step 2：启动 WebSocket ASR 服务

```bash
cd ~/dev/FunASR/runtime/python/websocket

# CPU 模式
python funasr_wss_server.py --port 10095 --device cpu

# GPU 模式（如有 CUDA）
python funasr_wss_server.py --port 10095 --device cuda --ngpu 1
```

服务启动后会加载 5 个模型（首次需下载）：
- 离线 ASR：`paraformer-zh`（SeACo，支持热词）
- 流式 ASR：`paraformer-large-online`
- VAD：`fsmn-vad`
- 标点：`ct-punc`（实时版）
- 说话人：`cam++`

启动完成会打印：`model loaded!`

### Step 3：启动 HTML5 演示页面

新开一个终端：

```bash
cd ~/dev/FunASR/runtime/html5
python h5Server.py --host 0.0.0.0 --port 1337
```

### Step 4：浏览器打开

```
https://127.0.0.1:1337/static/index.html
```

> 浏览器会提示证书不安全（自签名证书），点「高级」→「继续访问」即可。

页面操作：
1. 确认 WSS 地址为 `wss://127.0.0.1:10095/`
2. 选择模式（推荐 2pass）
3. 点击「连接」
4. 点击「开始」→ 开始说话
5. 点击「停止」→ 查看识别结果

## 三、服务端参数详解

```bash
python funasr_wss_server.py \
    --host 0.0.0.0 \
    --port 10095 \
    --device cpu \
    --ncpu 4 \
    --certfile ../../ssl_key/server.crt \
    --keyfile ../../ssl_key/server.key \
    --worker_threads 8 \
    --concurrent_asr_online 4 \
    --concurrent_asr_offline 2
```

### 核心参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--port` | 10095 | WebSocket 监听端口 |
| `--device` | cuda | 推理设备：`cuda` / `cpu` |
| `--ngpu` | 1 | GPU 数量，0 表示 CPU |
| `--ncpu` | 4 | CPU 线程数 |
| `--certfile` / `--keyfile` | ssl_key/ 下 | SSL 证书（浏览器要求 wss） |

### 并发控制参数

服务端使用线程池 + 信号量控制并发，避免 GPU 被打爆：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--worker_threads` | CPU 核心数 | 线程池大小 |
| `--concurrent_vad` | 4 | VAD 最大并发 |
| `--concurrent_asr_online` | 4 | 流式 ASR 最大并发 |
| `--concurrent_asr_offline` | 2 | 离线 ASR 最大并发 |
| `--concurrent_punc` | 1 | 标点模型最大并发 |

### 模型替换

```bash
# 使用自定义模型
python funasr_wss_server.py \
    --asr_model "iic/speech_paraformer-large-contextual_asr_nat-zh-cn-16k-common-vocab8404" \
    --asr_model_online "iic/speech_paraformer-large_asr_nat-zh-cn-16k-common-vocab8404-online" \
    --vad_model "iic/speech_fsmn_vad_zh-cn-16k-common-pytorch" \
    --punc_model "iic/punc_ct-transformer_zh-cn-common-vad_realtime-vocab272727"
```

## 四、Python 客户端

除了浏览器，还可以用 Python 客户端连接服务端：

```bash
cd ~/dev/FunASR/runtime/python/websocket

# 麦克风实时识别（需安装 pyaudio）
python funasr_wss_client.py --host 127.0.0.1 --port 10095 --mode 2pass

# 流式识别
python funasr_wss_client.py --host 127.0.0.1 --port 10095 --mode online --chunk_size "5,10,5"

# 离线识别文件
python funasr_wss_client.py --host 127.0.0.1 --port 10095 --mode offline \
    --audio_in "./data/wav.scp" --output_dir "./results"
```

### 客户端参数

| 参数 | 说明 |
|------|------|
| `--mode` | `online` / `offline` / `2pass` |
| `--chunk_size` | 流式分块大小，`"5,10,5"` = 600ms，`"8,8,4"` = 480ms |
| `--chunk_interval` | 发送间隔，值越大延迟越低但 CPU 越高 |
| `--audio_in` | 音频文件路径或 wav.scp，不传则用麦克风 |
| `--hotword` | 热词文件路径（每行格式：`关键词 权重`） |
| `--ssl` | 1 启用 SSL，0 禁用 |

### Python API 集成

在自己的 Python 程序中集成实时识别：

```python
from funasr_client_api import Funasr_websocket_recognizer

# 1. 创建识别器
rcg = Funasr_websocket_recognizer(
    host="127.0.0.1",
    port="10095",
    is_ssl=True,
    mode="2pass"
)

# 2. 发送音频数据（PCM 16kHz 16bit）
text = rcg.feed_chunk(pcm_data)
print("实时结果:", text)

# 3. 结束识别，获取最终结果
text = rcg.close(timeout=3)
print("最终结果:", text)
```

## 五、WebSocket 通信协议

理解协议才能集成到任意前端框架（React、Vue、小程序等）。

### 连接建立后，客户端发送初始配置

```json
{
    "chunk_size": [5, 10, 5],
    "wav_name": "microphone",
    "is_speaking": true,
    "chunk_interval": 10,
    "mode": "2pass",
    "itn": false,
    "hotwords": "{\"阿里巴巴\": 20, \"FunASR\": 30}"
}
```

| 字段 | 说明 |
|------|------|
| `chunk_size` | 流式分块参数，`[5,10,5]` 表示 600ms |
| `is_speaking` | true 表示开始说话 |
| `mode` | `online` / `offline` / `2pass` |
| `itn` | 是否启用逆文本标准化 |
| `hotwords` | JSON 字符串，热词及权重 |

### 持续发送音频数据

- 格式：PCM 16kHz 16bit 单声道
- 每次发送 960 bytes（即 30ms 音频）
- 通过 WebSocket 的 binary frame 发送

### 停止说话

```json
{
    "chunk_size": [5, 10, 5],
    "wav_name": "microphone",
    "is_speaking": false,
    "chunk_interval": 10,
    "mode": "2pass"
}
```

### 服务端返回结果

```json
{
    "text": "今天天气不错",
    "mode": "online",
    "is_final": false,
    "timestamp": [[0, 320], [320, 640], ...]
}
```

| 字段 | 说明 |
|------|------|
| `text` | 识别文本 |
| `mode` | 当前结果来自哪个模型：`online` / `2pass-offline` / `offline` |
| `is_final` | 是否为最终结果 |
| `timestamp` | 每个字的起止时间（毫秒） |

在 `2pass` 模式下，同一段语音会收到两次结果：先收到 `mode: "online"` 的实时结果，后收到 `mode: "2pass-offline"` 的纠正结果。前端应用时，用后者覆盖前者即可。

## 六、集成到自己的 Web 应用

### 需要搬走的文件

从 `~/dev/FunASR/runtime/html5/static/` 复制：

| 文件 | 作用 | 是否必须 |
|------|------|---------|
| `recorder-core.js` | 浏览器麦克风录音库 | 是 |
| `pcm.js` | PCM 编码插件 | 是 |
| `wsconnecter.js` | WebSocket 连接管理 | 可参考重写 |
| `main.js` | 主逻辑（录音→发送→接收） | 参考后重写 |
| `wav.js` | WAV 编码（文件上传模式用） | 按需 |

### 核心集成代码（精简版）

```javascript
// 1. 初始化录音器（PCM 16kHz 16bit）
const rec = Recorder({
    type: "pcm",
    bitRate: 16,
    sampleRate: 16000,
    onProcess: function(buffer, powerLevel, duration, sampleRate) {
        // 录音过程中持续调用
        const data16k = Recorder.SampleData(
            [buffer[buffer.length - 1]], sampleRate, 16000
        ).data;
        // 攒够 960 bytes 就发送
        if (ws.readyState === WebSocket.OPEN) {
            ws.send(data16k.buffer);
        }
    }
});

// 2. 建立 WebSocket 连接
const ws = new WebSocket("wss://your-server:10095/");

ws.onopen = () => {
    // 发送初始配置
    ws.send(JSON.stringify({
        chunk_size: [5, 10, 5],
        is_speaking: true,
        mode: "2pass",
        wav_name: "input_box"
    }));
    // 开始录音
    rec.open(() => rec.start());
};

ws.onmessage = (e) => {
    const result = JSON.parse(e.data);
    // 将识别文字填入输入框
    document.getElementById("your-input").value = result.text;
};

// 3. 停止录音
function stopRecording() {
    rec.stop();
    ws.send(JSON.stringify({
        chunk_size: [5, 10, 5],
        is_speaking: false,
        mode: "2pass"
    }));
    // 等待最终结果后关闭
    setTimeout(() => ws.close(), 3000);
}
```

### 注意事项

1. **HTTPS 要求**：浏览器的 `getUserMedia`（麦克风）必须在 HTTPS 页面中使用，所以 ASR 服务也必须用 `wss://`（即需要 SSL 证书）
2. **采样率**：浏览器麦克风采样率通常是 44.1kHz 或 48kHz，需要降采样到 16kHz。`recorder-core.js` 的 `Recorder.SampleData` 已处理了这个问题
3. **分块大小**：每 960 bytes（30ms）发送一次是推荐值，对应 `chunk_interval=10` 时 600ms 一个推理窗口
4. **热词**：如果你的场景有专业术语，通过 `hotwords` 字段传入可显著提高识别率

## 七、热词功能

热词可以在不重新训练模型的前提下，提升特定词汇的识别准确率。

### 在 HTML5 页面中使用

页面自带热词输入框，格式为每行一个词，空格隔开权重：

```
阿里巴巴 20
hello world 40
Paraformer 30
```

### 在客户端代码中使用

```bash
# 命令行客户端
python funasr_wss_client.py --host 127.0.0.1 --port 10095 \
    --mode 2pass --hotword hotwords.txt
```

hotwords.txt 格式同上。

### 在 WebSocket 协议中使用

初始配置的 `hotwords` 字段传入 JSON 字符串：

```json
{"hotwords": "{\"专业术语A\": 20, \"专业术语B\": 30}"}
```

权重值越大，该词被识别出的倾向越强。建议范围 10-50。

## 九、常见问题

### 浏览器提示「无法访问麦克风」

原因：非 HTTPS 页面无法使用 `getUserMedia`。确保通过 `https://` 访问 HTML5 页面。

### 连接 WSS 地址失败

1. 确认 ASR 服务已启动且端口正确
2. 浏览器需要先手动访问 `https://127.0.0.1:10095/` 接受自签名证书
3. HTML5 页面上的「点此处手工授权」链接也是做这个的

### iOS 手机无法录音

Safari 对 WebSocket + 录音有额外限制，需要先点页面上的「手工授权」链接。

### 识别延迟太高

- 检查 `chunk_size` 设置：`[8,8,4]` = 480ms 比 `[5,10,5]` = 600ms 延迟更低
- CPU 模式下延迟较高，建议使用 GPU
- 网络延迟：服务端尽量部署在近端
